# 专利导航报告——图表与可视化规范

本参考资料提供了专利导航报告中所有图表类型的规范，包括每种图表的使用场景、数据要求及格式标准。

---

## 1. 五类默认必备布局图

以下五类图是每篇专利导航报告的默认必备图，并优先于常规统计图完成。只有在检索后确认某类图确实没有数据支撑时，才可省略对应图；不得因报告类型、绘图工作量或已有其他图表而跳过。

**共同数据要求**：
- 以下字段是推荐数据集合；实际数据缺少非关键字段时，可使用已有字段生成简化图，或改用更适合现有数据的表达方式。
- 原始数据保存为 CSV，并另存带来源、口径、时间、单位和区域编码的 JSON 元信息。
- 每个指标尽可能回溯到 `search_strategy.md` 中的检索记录行或辅助数据来源。
- 区域名称统一到同一行政层级和标准名称；说明地图边界版本或地理编码来源。
- 所有图使用同一数据截止日期；跨年度指标注明年份口径。

### 1.1 产业链鱼骨图

**用途**：
- 展示上游原材料与装备、中游制造与关键部件、下游产品与应用场景之间的价值传导。
- 将关键技术、代表企业、专利密集环节和补链/强链/延链机会映射到产业链。

**默认结构**：
- 主骨从左向右依次布置上游、中游、下游，右侧“鱼头”为目标市场、核心产品、区域产业目标或需重点突破的终端应用。
- 主骨上方的刺骨可表示技术支撑、专利壁垒、人才与平台；下方的刺骨可表示重大项目、企业/品牌、原材料与装备约束。
- 每个节点应带可核验的标签；有专利数据时，可用括号或节点大小标注专利族数量、高价值专利数量或代表主体。

**数据要求**：
- `node_id`、`parent_id`、`level`、`node_name`、`chain_stage`、`technology_or_product`、`representative_entity`、`patent_family_count`、`data_year`、`source_id`。
- 至少覆盖上游、中游、下游三层；无法确认的节点标注“待核验”，不得虚构产业链关系。

**格式标准**：
- 节点和箭头避免交叉遮挡，文字优先横排；节点过多时按一级环节拆分或突出关键路径，不缩小到不可读。
- 用颜色区分上游、中游、下游和支撑环节；图内 title 使用“XX产业链结构与技术支撑”，不得带图号。
- 图后必须解释主导环节、薄弱环节、关键卡点和可进入的强链/补链/延链位置。

### 1.2 产业区域分布图

**用途**：
- 展示专利族、创新主体、产业产值、企业数量或创新平台在目标国家、省、市间的空间分布。
- 支撑全球—国家—省—市的四级地理递进分析。

**数据要求**：
- `region_name`、`region_code`、`region_level`、`metric`、`value`、`unit`、`data_year`、`data_cutoff`、`source_id`、`boundary_version`。
- 指标必须写明是专利族数量、申请量、有效发明量、企业数量、产值还是其他口径；不得把不同指标混在同一色阶中。
- 使用可比口径时，可增加人均、每万人口发明专利拥有量或占比等归一化指标。

**格式标准**：
- 默认使用分级统计地图（choropleth）；地图缺少可用边界时，改用带区域编码的排序气泡图或行政区示意分布图，并在图注说明。
- 使用顺序色阶表示强度，标注 TOP-10 区域或关键目标区域；对同一图内的区域采用统一行政边界版本。
- 图后必须解释集聚中心、薄弱区域、空间梯度及其与产业链环节的关系。

### 1.3 重大项目分布图

**用途**：
- 展示重大项目在区域上的落点、投资强度、建设状态、技术方向和实施时间。
- 识别项目集聚区、产业链补短板项目及潜在创新资源导入点。

**数据要求**：
- `project_name`、`region_name`、`region_code`、`latitude`、`longitude`（如可获得）、`investment`、`investment_unit`、`start_year`、`status`、`technology_direction`、`chain_stage`、`source_id`、`data_year`。
- 只有区县或城市级信息时，不得伪造经纬度和精确点位；应使用城市/区县质心或行政聚合分布，并在图注说明定位精度。
- 项目状态应统一，例如规划、在建、投产、暂停；投资指标必须注明币种、单位和统计口径。

**格式标准**：
- 可使用地图气泡图：位置表示区域，气泡大小表示投资额或项目规模，颜色表示技术方向或建设状态。
- 图例必须解释大小与颜色；标注代表性项目，避免标注重叠。
- 图后必须解释项目是否与产业链关键环节匹配、是否存在项目空档或重复布局。

### 1.4 重点企业（人才）分布图

**用途**：
- 展示重点企业、研发机构、创新平台及核心发明人/团队的空间集聚和协同生态。
- 支撑招商引资、主体培育、人才引进和产学研合作建议。

**数据要求**：
- 企业层：`entity_name`、`entity_type`、`region_name`、`region_code`、`patent_family_count`、`high_value_patent_count`、`main_technology`、`source_id`。
- 人才层：`talent_or_team`、`affiliation`、`region_name`、`region_code`、`patent_family_count`、`core_technology`、`cooperation_scope`、`source_id`。
- 人才数据仅使用公开专业信息，按工作机构或专利发明人地址聚合到城市/区县；不得推断个人住址或披露非必要个人信息。

**格式标准**：
- 企业、机构、人才分别使用不同标记形状或色系；同时展示时使用双层叠加图，必须有图例。
- 点大小可表示专利族数量、重点人才数量或创新平台等级；避免用未定义指数制造“人才排名”。
- 图后必须解释企业—人才—平台的空间耦合、核心节点和供需错配。

### 1.5 产品品牌分布图

**用途**：
- 展示产品类别、品牌、企业、技术分支和典型应用之间的对应关系。
- 识别高价值产品赛道、品牌集中度、企业产品覆盖和专利支撑关系。

**数据要求**：
- `product_category`、`product_or_application`、`brand`、`enterprise`、`chain_stage`、`patent_family_count`、`market_indicator`（如可获得）、`source_id`。
- 品牌与企业的隶属关系须有来源；“品牌未公开”不得强行补全为知名企业。

**格式标准**：
- 默认采用“产品类别 × 品牌/企业”的气泡矩阵或产品—品牌桑基/网络图；需要地域含义且用户明确要求时再使用地图。
- 气泡大小表示专利族、产品数量或其他已定义指标；颜色表示产业链环节、品牌归属或技术方向。
- 图后必须解释产品—品牌—专利的对应强弱、空白赛道和可能的品牌培育方向。

**五类必备图使用规则**：
- 五类图默认分别保存图片和数据文件，全部纳入报告。
- 只有确认某类图确实没有数据支撑时，才可省略对应图；其他图仍须正常生成。
- 不得为了生成某类图而虚构项目坐标、主体、品牌关系或统计值。
- 某类图确实无数据时，可在检索表“结果/备注”列简述原因并省略；不得生成空白图或装饰性占位图。

## 2. 通用分析图表类型目录

### 2.1 折线图

**使用场景**：
- 专利申请量随时间变化趋势
- 技术生命周期发展轨迹
- 多区域趋势比较

**数据要求**：
- X轴：时间（年份或月份）
- Y轴：数量或百分比
- 多条数据系列进行比较

**格式标准**：
- 线条粗细：主要系列2-3px，次要系列1.5px
- 数据标记：仅在关键拐点处显示数据点
- 颜色：各系列使用不同颜色，并配图例
- 标注：直接在图表上添加阶段标签（萌芽期、加速期、爆发期）

---

### 2.2 柱状图

**使用场景**：
- TOP-N申请人排名
- IPC分类号分布
- 区域专利量比较

**数据要求**：
- 分类轴（申请人名称、IPC分类号、区域）
- 数值（专利数量、百分比）

**格式标准**：
- 默认按降序排列
- 在柱上显示数值标签
- 相关图表间使用一致的配色方案
- 为便于阅读，限制显示TOP-10或TOP-20

---

### 2.3 横向柱状图

**使用场景**：
- 申请人名称较长时（提高文本可读性）
- 带有详细标签的比较排名

**格式标准**：
- 从上到下按降序排列
- 必要时截断长标签并加省略号
- 在柱状图末端显示数值标签

---

### 2.4 饼图

**使用场景**：
- 专利类型分布（发明/实用新型/外观设计）
- 申请人类型分布（企业/高校/科研院所）
- 法律状态分布（有效/失效/审查中）

**数据要求**：
- 整体中的组成部分（各部分之和必须为100%）
- 最多限制为5-7个扇区

**格式标准**：
- 显示百分比标签
- 突出显示重要扇区
- 跨报告使用一致的配色映射

---

### 2.5 堆叠柱状图

**使用场景**：
- 时间窗口内的主题占比演变
- 跨区域的多类别比较
- 按区域划分的专利价值等级分布

**数据要求**：
- 每组包含多个类别
- 类别之间应互斥

**格式标准**：
- 每个类别使用不同的颜色
- 包含图例
- 空间允许时在柱上显示总值

---

### 2.6 S型曲线图

**使用场景**：
- 技术生命周期分析
- 创新广度与创新强度映射

**数据要求**：
- X轴：独特申请人数量（创新广度）
- Y轴：专利申请量（创新强度）
- 带有阶段标签的时间序列轨迹

**格式标准**：
- 绘制带有时间标注的轨迹线
- 标记阶段边界（导入期、成长期、成熟期、衰退期）
- 使用箭头指示轨迹方向
- 直接在图表上添加阶段标签

---

### 2.7 热力图

**使用场景**：
- IPC密度矩阵（IPC分组 × 时间段）
- 区域技术聚焦比较
- 技术关联性分析

**数据要求**：
- 两个分类维度
- 数值强度值

**格式标准**：
- 使用顺序颜色标度（浅色→深色）
- 在单元格内包含数值标签
- 添加行合计和列合计

---

### 2.8 雷达图

**使用场景**：
- 多维度的创新能力比较
- 区域竞争力评估

**数据要求**：
- 最多5-8个维度
- 归一化数值（0-100标度）

**格式标准**：
- 使用半透明填充区域
- 按20%间隔显示网格线
- 清晰标注每个维度

---

### 2.9 散点图

**使用场景**：
- 专利数量与质量相关性分析
- 技术集中度与多元化分析
- 创新投入与产出分析

**数据要求**：
- 两个连续变量
- 可选气泡大小表示第三维度

**格式标准**：
- 标注关键数据点
- 若存在相关性，添加趋势线
- 使用颜色编码区分类别

---

### 2.10 网络图

**使用场景**：
- 共同申请人合作网络
- 引文网络
- 技术共现关系

**数据要求**：
- 节点（实体）和边（关系）
- 边权重表示关系强度

**格式标准**：
- 节点大小与中心度成正比
- 边粗细与关系权重成正比
- 按类别对节点进行颜色编码
- 使用力导向布局

---

### 2.11 流向图

**使用场景**：
- 区域间的技术转移
- 专利转让流向
- 跨境许可模式

**数据要求**：
- 源实体和目标实体
- 流量值

**格式标准**：
- 使用带比例的曲线箭头
- 按类别进行颜色编码
- 包含流量值标签

---

### 2.12 统计表

**使用场景**：
- 带有多个指标的TOP-N排名
- 政策文件时间线
- 企业概况摘要

**格式标准**：
- 为便于阅读，行颜色交替显示
- 标题行加粗
- 数字右对齐，文本左对齐
- 表格下方标注来源

---

## 3. 图表编号体系

### 规范
- 图：图X-X（Figure X-X，其中第一个X为章节号）
- 表：表X-X（Table X-X）
- 每章内按顺序编号

### ⚠️ 关键约束：编号不得进入图表图片本身
- **"图X-X"编号仅用于 Markdown 正文中的图片引用语法和图片下方的题注（caption）中。**
- **生成的图表图片文件（PNG/SVG）自身的标题（title）中严禁包含"图X-X"、"图1-1"、"图2-3"等编号标签。**
- **图表图片的 title 只能是纯描述性文字**（如"全球碳纤维专利申请量趋势"），不得带任何编号前缀。
- **正确示例**：
  - 图片文件内的 matplotlib title：`全球碳纤维专利申请量趋势（{TIME_RANGE_START}-{TIME_RANGE_END}）`（年份取需求文档中的分析窗口，勿照抄固定样例年）
  - Markdown 正文中的引用：`![图7-1 全球碳纤维专利申请量趋势](/mnt/user-data/workspace/patent_navigation/assets/charts/fig_7_1_trend.png)`
- **错误示例**：
  - ❌ 图片文件内的 matplotlib title：`图7-1 全球碳纤维专利申请量趋势`（编号进入了图片，禁止）
  - ❌ 题注或 JSON 写死与需求无关的静态日期（必须使用需求文档中的**数据截止日期**；未指定时使用 `<current_date>`）

### 示例
- Markdown 引用：`![图7-1 全球碳纤维专利申请量趋势](.../fig_7_1_trend.png)` — "图7-1"在 Markdown 层面
- 图表图片内部 title：`全球碳纤维专利申请量趋势` — 纯描述性文字，无编号

## 5. 图表标注标准

### ⚠️ 核心原则：图表图片与 Markdown 题注分离

图表图片（PNG/SVG）与 Markdown 中的图表引用各有分工，职责严格分离：

| 内容 | 放在哪里 | 说明 |
|------|----------|------|
| 图表 title（描述性标题） | 图表图片内部 | 纯描述文字，如"全球碳纤维专利申请量趋势" |
| 图号/表号（图X-X/表X-X） | Markdown 题注中 | 编号 + 描述，如 `![图7-1 全球碳纤维专利申请量趋势](...)` |
| 数据来源 | Markdown 题注中 | 如 `*数据来源：智慧芽专利数据库*` |
| 坐标轴标签/单位 | 图表图片内部 | X/Y 轴标注 |

### 强制性标注（图表图片内部）
- **图表 title**：纯描述性名称，严禁包含"图X-X"等编号前缀
- **坐标轴标签**：必须带单位
- **图例**：多系列图表必须有图例

### 强制性标注（Markdown 题注中）
- **图号/表号**：使用"图X-X"或"表X-X"格式
- **数据来源**：标注数据出处（例如："数据来源：智慧芽专利数据库"）
- **数据截止日期**：优先采用需求文档中的「数据截止日期」，未指定时使用生成当日 `<current_date>`，格式为 `YYYY-MM-DD`；**禁止**照抄本规范中的静态日期；**禁止**用「时间范围」窗口终点或固定年中日冒充截止日；各章图注截止日必须全文统一

### 可选标注
- 趋势图上的阶段标签
- 关键拐点标记
- 因果解释标注
- 比较基准

## 6. 图表位置指南

### 章节内结构
1. 图表应紧跟在首次提及该图段落后放置
2. 图表图片通过 Markdown 图片语法 `![...](path)` 引用
3. **图表图片内部的 title 仅为纯描述性文字**（如"全球碳纤维专利申请量趋势"），**不得包含图号/表号**
4. **图号/表号与题注放在 Markdown 中**，紧跟在图片语法下方，采用 `*图X-X 描述性标题。数据来源：XXX*` 格式
5. 每个图表后附简要解读文字

### 正文引用格式
- "如图7-1所示，全球碳纤维专利申请量呈现明显的三阶段增长特征。"
- "由图7-1可见，2010年是中国专利申请量的转折点。"
- "这主要得益于国家政策的持续支持和产业资本的加速进入。"

### 图表题注格式（Markdown，在图片下方）
```markdown
![图表图片引用](/mnt/user-data/workspace/patent_navigation/assets/charts/fig_7_1_trend.png)

*图7-1 全球碳纤维专利申请量趋势。数据来源：智慧芽专利数据库，数据截止{DATA_CUTOFF}*
```
其中 `{DATA_CUTOFF}` 替换为需求文档「数据截止日期」；未指定时替换为 `<current_date>`，不要写成固定的示例日期。

**注意**：上方 `![](...)` 中的 alt 文本和下方 `*...*` 中的题注均包含"图7-1"，但**图表图片文件自身的 title 不含"图7-1"**。

## 7. 图表资产保存规范

### 7.1 图表文件保存路径

- 使用英文小写和下划线
- X_X 为图号/表号（如 fig_1_1、table_2_3）

### 7.3 正文引用格式

```markdown
![图5-1 全球碳纤维专利申请趋势（{TIME_RANGE_START}-{TIME_RANGE_END}）](/mnt/user-data/workspace/patent_navigation/assets/charts/fig_5_1_trend.png)

[citation:Patsnap Database](https://www.zhihuiya.com/)
```

**⚠️ 注意**：Markdown 的 `![...]` alt 文本和下方 `*...*` 题注中都包含"图5-1"编号，这符合规范。但**图表图片文件（fig_5_1_trend.png）内部通过 matplotlib 设置的 title 必须仅为描述性文字（可含分析窗口年份），严禁包含"图5-1"编号前缀**。即：
- 图片文件内部 title：`全球碳纤维专利申请趋势（{TIME_RANGE_START}-{TIME_RANGE_END}）` ✅（年份来自需求「时间范围」）
- 图片文件内部 title：`图5-1 全球碳纤维专利申请趋势（{TIME_RANGE_START}-{TIME_RANGE_END}）` ❌
- 题注写死与需求无关的静态日期 ❌（须用 `{DATA_CUTOFF}` / 需求文档日期或 `<current_date>`）

### 7.4 数据文件内容要求

CSV文件应包含生成图表所用的完整数据：
```csv
year,global,china,japan,usa
1990,120,0,80,40
1991,135,5,82,42
...
```

JSON文件应包含结构化的数据和元信息：
```json
{
  "chart_id": "fig_5_1",
  "title": "全球碳纤维专利申请趋势",
  "chart_type": "line",
  "data_source": "智慧芽专利数据库",
  "data_cutoff": "{DATA_CUTOFF_ISO}",
  "x_axis": "年份",
  "y_axis": "专利申请量（件）",
  "series": ["全球", "中国", "日本", "美国"],
  "data": [...]

```
其中 `{DATA_CUTOFF_ISO}` 替换为 `YYYY-MM-DD` 格式的实际数据截止日期；优先采用需求文档日期，未指定时使用 `<current_date>`，禁止写死规范示例日期。

## 9. 中文字体渲染配置（强制）

专利导航报告包含大量中文内容（标题、坐标轴标签、图例、数据标签等），必须正确配置中文字体，否则图表中的所有中文都会显示为方块乱码。

### 9.1 字体选择

优先使用以下中文字体（按优先级排列）：

| 优先级 | 字体名称 | 适用系统 | 安装方式 |
|--------|----------|----------|----------|
| 1 | Noto Sans CJK SC | Linux (通用) | `apt install fonts-noto-cjk` |
| 2 | WenQuanYi Micro Hei | Linux | `apt install fonts-wqy-microhei` |
| 3 | WenQuanYi Zen Hei | Linux | `apt install fonts-wqy-zenhei` |
| 4 | SimHei | Linux/Windows | 通常已安装或手动下载 |
| 5 | Microsoft YaHei | Windows | 通常已安装 |
| 6 | PingFang SC | macOS | 系统自带 |
| 7 | Heiti SC | macOS | 系统自带 |

### 9.2 matplotlib 字体配置（Python 绘图脚本必须执行的初始化代码）

**每份 Python 绘图脚本开头必须**包含以下字体配置代码：

```python
import matplotlib
matplotlib.use('Agg')  # 非交互式后端，避免 GUI 依赖
import matplotlib.pyplot as plt
import matplotlib.font_manager as fm

# === 中文字体配置（强制，不可省略）===
def setup_chinese_font():
    """
    配置 matplotlib 中文字体。按优先级自动检测可用字体。
    必须调用此函数后再进行任何绘图操作。
    """
    # 按优先级检测可用中文字体
    candidate_fonts = [
        'Noto Sans CJK SC',
        'WenQuanYi Micro Hei',
        'WenQuanYi Zen Hei',
        'SimHei',
        'Microsoft YaHei',
        'PingFang SC',
        'Heiti SC',
        'AR PL UMing CN',
        'AR PL UKai CN',
    ]

    available_fonts = [f.name for f in fm.fontManager.ttflist]
    selected_font = None

    for font_name in candidate_fonts:
        if font_name in available_fonts:
            selected_font = font_name
            break

    if selected_font is None:
        # 最后兜底：尝试通过通配查找任何可用的 CJK 字体
        cjk_fonts = [f for f in fm.fontManager.ttflist
                     if any(kw in f.name.lower() for kw in ['cjk', 'hei', 'ming', 'song', 'kai', 'fang', 'chinese', 'cn', 'sc'])]
        if cjk_fonts:
            selected_font = cjk_fonts[0].name
        else:
            raise RuntimeError(
                "未找到任何可用的中文字体！"
                "请执行: sudo apt install fonts-noto-cjk fonts-wqy-microhei"
            )

    plt.rcParams['font.sans-serif'] = [selected_font]
    plt.rcParams['font.family'] = 'sans-serif'
    plt.rcParams['axes.unicode_minus'] = False  # 解决负号 '-' 显示为方块的问题
    plt.rcParams['mathtext.default'] = 'regular'  # 数学文本使用常规字体

    print(f"[字体配置] 使用中文字体: {selected_font}")
    return selected_font

# 在脚本开始处调用
FONT_NAME = setup_chinese_font()
```
